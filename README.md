# 武侯Chat

> 加密传输与存储的匿名聊天空间（密钥托管 · 平台可依法审计）· **Copyright © 2026 左熙宇 · 保留所有权利**

一套前后端完整的即时通讯系统：Python（FastAPI + aiohttp WebSocket + Redis + RabbitMQ + ftplib）
服务端，零依赖构建的现代 Web 前端，支持桌面 / 平板 / 手机多端自适应。

## 一、快速启动

```bash
# 1. 安装依赖（项目已自带 venv 时跳过）
python -m venv venv
venv\Scripts\pip install fastapi uvicorn aiohttp aio-pika redis aiosqlite pyjwt bcrypt python-multipart pydantic-settings

# 2. 启动（同一事件循环内同时运行 HTTP 与 WebSocket 网关）
venv\Scripts\python run.py            # HTTP :8000  ·  WS :8001

# 3. 打开浏览器
#    http://127.0.0.1:8000
```

Redis / RabbitMQ **未安装也能运行**：存储与消息总线会自动降级为进程内实现，功能完整。
安装后无需改代码，重启即自动切换（`redis://127.0.0.1:6379/0`、`amqp://guest:guest@127.0.0.1:5672/`）。

管理员入口：左侧导航「🛡️ 管理」，默认账号 `admin` / `wuhou@2026`（可在 `.env` 用 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 覆盖）。

端到端冒烟测试：`venv\Scripts\python tools/smoke_test.py`（55 项断言，覆盖注册登录、好友、群聊、密钥分发、消息、文件、动态、搜索、风控、管理员）。
另有浏览器端到端套件（`tools/*_check.js`，用 CDP 驱动真实 Edge）：群密钥 `group_keys_check.js`、群邀请重钥 `group_invite_key_check.js`、群管理员与公告 `group_admin_check.js`、好友分组标签 `friend_tags_check.js`、会话草稿与 @提及 `draft_mention_check.js`、语音 `voice_msg_check.js`、表情回应 `reaction_check.js`、界面巡检 `ui_round_check.js`、V2 三功能 `v2_trio_check.js`（79 项：动态二级评论 / 生日提醒 / 名片推荐好友）。
**移动端专项 `mobile_ui_check.js`**（60 项断言，390×844 移动视口 + 触摸模拟）：认证页贴合视口、底部玻璃 tabbar、列表抽屉手势（边缘右滑唤出 / 左滑收起 / 点抽屉外收起）、主区卡片退让、弹层底部化（modal / sheet / 长按菜单）、长按 = 右键、16px 防缩放、无横向溢出、回桌面形态全部退场。

## 二、加密与密钥托管

> **设计取舍**：严格的「服务端不可解密」会让违规判定、举报核查、风控全部失效。
> 因此 V2.0 保留会话级密钥的工程结构（便于后续做成员变更重钥、前向安全），
> 同时**把密钥托管给服务端** —— 内容在传输与落库环节仍是密文，
> 但平台可解密用于内容治理。托管密钥对落盘在 `data/escrow.json`。

| 场景 | 方案 |
| --- | --- |
| 身份密钥 | 注册时在浏览器用 WebCrypto 生成 **RSA-OAEP-2048**；私钥用「登录口令 PBKDF2(120k) 派生的 AES-256-GCM」加密为 keyblob 上送服务端（跨设备恢复），同时用本机随机设备密钥加密落 IndexedDB（刷新免输密码）。**服务端只持有公钥，私钥永不出端** |
| 私聊 | 每个会话一把随机 AES-256-GCM 密钥，按收件人公钥逐个包裹（`keys` 字段）；同时用服务端托管公钥再包一份（`keys.__escrow`） |
| 群聊 | 每群一把随机 AES-256-GCM 群密钥，按成员公钥逐个包裹（`gkey:{gid}:{uid}`）；每个成员 extra 用服务端托管公钥再包一份（`__escrow`）。密钥带版本号 `gkeyver`，成员变更会触发重钥，移除的成员用旧密钥解不开新消息 |
| 公共聊天室 | 同群聊，走全局统一密钥 |
| 文件 | 图片 / 视频 / 任意文件在浏览器内 AES-GCM 加密后上传，服务端保存不透明字节流 |
| 动态 | 正文与媒体用随机密钥加密，密钥按可见好友逐个包裹；评论复用该动态密钥 |
| 聊天记录搜索 | 服务端仅索引元数据；**正文命中在浏览器本机解密索引（IndexedDB）完成**，两路结果合并展示 |
| 头像 / 群头像 | 属公开资料，TLS 传输 + 加密落盘，不做 E2EE（需对任意访客可见） |

## 三、功能清单

- **两套独立界面系统**：电脑端与移动端是**两份彼此独立的实现**，不是同一份 DOM 的响应式补丁。电脑端是「左侧图标栏 + 中间列表 + 右侧内容」的同屏三栏；移动端是 App 形态（标准顶栏 + 页面栈 + 底部 4 标签 + 右侧抽屉），信息结构、导航语言、顶栏与弹层形态都不一样。形态由 `formfactor.js` 单点判定（URL `?ff=` > 本地偏好 > 视口规则），`<html class="is-mobile|is-desktop">` 是唯一开关，某套界面挂载时另一套整棵退出舞台（`#app { display:none }`），改一套不会牵动另一套。
- **移动端交互**：左缘右滑返回、弹层下拉关闭（动作单 / 长按菜单 / 弹窗一律底部抽屉）、长按气泡 = 右键菜单（动作出口仍只有菜单这一个）、软键盘弹起时底部标签栏让位、输入框统一 16px（避开 iOS 自动缩放）、`env(safe-area-inset-*)` 适配刘海与安全区、列表项加高到手指可靠命中区
- **登录 / 注册**：用户名 + 密码 + 昵称 + 年龄 + 性别 + 生日 + 头像（表情或加密上传）+ **滑动人机检测**（服务端纯 Python 绘制 PNG 拼图，答案不出服务端，一次性票据 + 轨迹校验 + 时长校验）
- **私聊**：文本、图片 / 视频 / 文件传输（附件保留 30 天，`FILE_RETENTION_SECONDS` 可调；下载带 `Content-Disposition`，中文文件名按 RFC 5987 编码）、表情包与自定义表情包、语音 / 视频通话、语音消息、表情回应、拍一拍、引用、撤回（2 分钟内）、会话草稿
- **群聊**：群主特权（入群方式 free/approval/invite、禁言与全员禁言、添加 / 踢出成员、撤回成员消息、群介绍 / 群头像 / 可发现性、解散群聊），副管理员角色、群公告、文件传输、表情包、多人音视频、拍一拍、引用、撤回
- **动态（朋友圈）**：文字 + 图片 / 视频（最多 9 张）、好友点赞 / 评论、转发至好友或群聊
- **动态二级评论**：评论可回复（层级封顶两级，回复的回复并回同一根下并标注「回复 @某人」）、级联删除（删根评论连带其下回复）、动态作者可清理任意评论、前端树形渲染 + 长列表折叠
- **生日提醒**：好友生日聚合（今天 / 7 天内 / 更远），通讯录卡片高亮今日生日、侧栏入口、资料卡生日倒计时（含周岁提醒）
- **名片推荐好友**：资料卡一键把 TA 的名片以端到端加密富消息发给其他好友或群聊，接收方在聊天里直接查看资料 / 发消息 / 加好友
- **全局搜索**：用户（昵称 / 用户名）、群聊（群名）、聊天记录（服务端元数据 + 本机解密正文）、动态
- **添加好友卡片**：按钮触发，可自定义申请留言
- **加入群聊卡片**：按钮触发，可自定义入群申请
- **用户信息卡片**：点击头像触发，展示用户名 / 昵称 / 年龄 / 性别 / 生日 / 头像 / 个性签名；自己可编辑，好友可设置备注 / 拉黑，陌生人可加好友
- **群聊信息卡片**：群头像 / 名称 / 成员数 / 介绍 / 成员网格；自己的群可编辑，已加入可备注 / 退出，未加入可申请加入
- **在线 / 离线状态**：WebSocket 心跳 + 好友上下线实时推送
- **用户设置卡片**：个人中心（资料 / 头像 / 拍一拍后缀 / 修改密码 + 私钥重新封装）、安全中心（登录设备管理 + 设备登录状态删除、二次登录第二层密码）、拉黑用户管理、注销账号
- **好友分组标签**：给好友打自己的私人分组（最多 20 组、5 种配色，组名违规词拦截）。通讯录按「全部 / 某分组 / 未分组」筛选并显示成员数，联系人与资料卡展示标签 chip；删除分组或删除好友都会自动清理归属。分组还能直接用于**动态可见范围**（「按分组可见」），发布瞬间展开成具体好友名单。
- **会话草稿**：输入框内容实时加密同步（`drafts:{uid}` 单文档，per-conv），切换会话 / 刷新 / 关页面都不丢；会话列表显示 `[草稿]`；发送成功自动清除，发送失败把原文还给输入框并存成草稿
- **@提及**：输入 `@` 唤起成员候选（群聊含 **@所有人**，支持昵称过滤与 ↑↓/回车/Tab 键盘导航），气泡内 `@昵称` 高亮可点开资料卡；名单同密上报，服务端托管解密后做成员校验并给被提及者打 `[有人@我]` 标记，读取会话后清除
- **公共聊天室（武侯祠）**：全员聊天室，表情包 / 拍一拍 / 引用 / 撤回，支持系统公告
- **违规词检测**：服务端明文字段（昵称 / 签名 / 群名 / 群介绍 / 申请留言）拦截；聊天正文由客户端本地词库前置提示，**并在服务端解密后二次判定，命中即拒绝发送**（`badword_action_chat`）
- **WAF**：判定权 100% 交给 `WuhouShield/`（**智盾WAF v10.2 Ultra 企业定制版本**，:9200）—— 请求进来由它判定，说拦就拦；本站不再内置第二套规则。覆盖 SQL 注入 / XSS / 命令注入 / 路径穿越 / SSRF / XXE / SSTI / 反序列化 / WebShell / Log4j 等 CVE / 扫描器指纹 / 请求走私，以及 @轰炸、批量拉人、零宽字符隐写等 IM 业务滥用。中间件另负责 IP 限流，**全局不自动封禁 IP**
- **举报机制**：用户 / 群聊 / 聊天记录 / 动态四类举报，管理员处置台
- **定制版WAF（`WuhouShield/`）**：把智盾WAF v10.2 Ultra 的检测核心**提取出来重写**的独立实现（独立进程 :9200、独立密钥、独立状态文件），运行时不依赖也不访问任何第三方系统 —— `DDos_WAF/` 只是核心代码的来源，不是运行依赖。相对原版智盾修掉了三处会让本站**完全不可用**的误判（后台 `/app/admin` 被判敏感路径、中文被判编码绕过、嵌套 JSON 被判注入），并让密文与随机 base64 不再被解码误判
- **管理员**：独立登录接口与控制台（概况、用户封禁 / 删除 / 重置密码、群聊隐藏 / 解散、举报处置、违规词库管理、系统公告）；后台是**独立入口** `/app/admin`（独立鉴权），普通用户的「关于」页不再出现任何后台入口。WAF 不在后台设页签，概况页只留一行状态 + 「打开控制台」入口，完整界面在 `/app/waf`。后台视觉与主站同一套设计令牌：分段式页签、渐变数字统计卡、状态呼吸点、淡染描边操作按钮，主题跟随站点设置（深 / 浅 / 极光）

### WAF 界面（只有一处：独立控制台 `/app/waf`）

WAF 有自己的界面系统，不在管理员后台设页签 —— 两套界面重复维护同一批功能，
改一处忘一处只会造成不一致。后台概况页保留一行「WAF 防护」状态和一个
「打开控制台」按钮作为入口，仅此而已。

侧栏导航 + 大信息密度内容区，独立视觉层（`static/css/waf.css`），跟随站点主题。
身份复用管理员令牌（不为 WAF 另设账号，因此**没有**第二个登录入口）：

1. **概况** —— 防护状态 Hero、六项运行指标、近一小时拦截趋势（分桶柱状）、
   攻击类型分布、主要攻击来源、最近拦截；每 15 秒自动刷新；
2. **攻击事件** —— 按级别 / 关键词筛选，可直接从事件封禁来源 IP；
3. **封禁管理** —— 列表、手动封禁（IP / 时长 / 原因）、解封、全部解封；
4. **白名单** —— 增删；
5. **规则库** —— 搜索 + 按分类浏览；
6. **实时检测** —— 自填一段请求（方法 / 路径 / 查询串 / 请求体 / 来源 IP）交给检测服务
   判一次，看它拦不拦、命中哪条规则；内置 SQL 注入 / XSS / 路径穿越 / 命令注入 /
   正常请求 / 中文 / 嵌套 JSON 快速用例；
7. **服务设置** —— 服务信息、接口密钥（掩码 / 明文 / 复制）、链路自检。

**没有「防护强度」页**：手动调档是唯一能一键把访客挡在门外、甚至把管理员自己锁在
门外的操作，而强度本来就由系统按流量自动调整；手动选过还会固定住档位不再自适应。
因此控制台不提供手动调档入口，只在「服务设置」里**只读**显示当前档位。
后端 `panel/defense_level` 接口保留（自检与自动调整仍在用）。

「链路自检」跑五条固定用例（四类攻击 + 一条正常请求），走的是**探测模式**
（`/api/detect` 带 `probe=true`）：只问规则引擎，跳过封禁名单等处置闸且不记账。
原因很实在 —— 自检用固定样例 IP，只要这个 IP 被封过一次，五条用例就全由
「封禁名单」判死：正常请求被判攻击（谎报误杀，还会误导管理员去调低防护强度），
四类攻击也不是被规则拦住的（自检变成假阳性）。不记账则是为了让自检的假攻击
不灌进事件流、不把趋势图和「主要攻击来源」带偏。「实时检测」相反，走完整处置闸，
管理员才能照真实行为排查「这个接口为什么被拦」。

读的、写的都是**定制版自己的状态**，不代理任何第三方系统。后台代理路径为
`GET|POST|PUT|DELETE /api/admin/waf/panel/{path}`，定制版的接口密钥只出现在服务端、
不下发浏览器。`/api/admin/waf/*` 在拦截判定中整体跳过 —— 这些是安全工具自己的接口，
「实时检测」要把攻击样本原样提交上来判一次，不跳过的话会被 WAF 先拦掉。

启动顺序（Linux 部署）：先起定制版 `tools/start_wuhou_shield.sh`，再起武侯Chat `tools/start_chat.sh`。

## 五、安全说明

- 服务端存储密文与被公钥包裹的密钥；私聊会话密钥另附**托管信封**（服务端 RSA 公钥包裹），因此平台具备解密能力，仅用于违规检测与举报核查
- 托管私钥落盘于 `data/escrow.json`，等同于全站内容的万能钥匙，需与数据库同级别保管；删除该文件将重新生成，旧托管信封随之失效
- 令牌：JWT HS256（7 天）；WS 换票一次性、90 秒有效
- 密码：bcrypt（SHA-256 预哈希）或 PBKDF2-HMAC-SHA256 210k 迭代
- 上传：200MB 上限、IP 限流、定制版WAF 判定拦截
- WAF 可用性：定制版离线 / 熔断时**不做拦截**（fail-open，本站已无内置规则兜底），以保证全站可用；因此 `WuhouShield/` 必须常驻，管理员应在控制台确认首屏为「防护正常」
- 全局不封禁 IP：定制版 `auto_ban_enabled=False`，不会自动拉黑任何来源；封禁只能由管理员手动决定，本机与白名单地址一律拒绝封禁
- 锁定档（L5）也会放行本机回环：任何防护强度都不切断管理员自己的回路，否则站点会变成不可恢复状态（有回归断言盯着）
- 生产部署请：更换 `SECRET_KEY` 与管理员口令、收紧 `CORS_ORIGINS`、启用 HTTPS（WebCrypto 依赖安全上下文，`127.0.0.1` 除外）
